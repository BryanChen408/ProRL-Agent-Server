# AscendC 算子实现模式

本文把 cannbot 的实现参考整理为算子结构到 kernel 方案的路由。它只补充实现知识，不改变
Polar 的任务契约或验证流程。

## 归约：先拆成 `(O, R, I)`

把归约轴前的维度乘积记为 `O`，归约长度记为 `R`，归约轴后的内维乘积记为 `I`。

- `I > 1`：按 `(O, R, I)` 做跨行归约，按 `I` 分 tile；通常不做物理转置。
- `I == 1` 且一行可放入 UB：批量装入多行后做末轴归约。
- `I == 1` 且一行超过 UB：分块累加，再做第二级归约。
- padding 必须符合语义：sum 用 0，max 用负无穷，min 用正无穷，prod 用 1。
- FP16/BF16 归约优先使用 FP32 累加，最后按 reference 的 dtype 和舍入语义转换。
- 分块循环避免逐元素读回和每块 `PIPE_ALL`；用向量累加器和方向明确的同步。
- 行距、输出地址和 DataCopy 的对齐单位要分别核对，不能把元素、字节和 32B block 混用。

## Norm 与激活融合：两遍数据流

GroupNorm、LayerNorm、RMSNorm 及其激活融合通常分成：

1. 第一遍读取输入，计算统计量；
2. 第二遍应用归一化、affine 和激活并写出。

实现时：

- 统计量和中间累加使用合适的高精度累加器；
- affine 可以合并为一次乘加，但必须保持 reference 的计算顺序和 dtype；
- 大空间维按运行时 tile 分片，不能按训练 case 的最大 shape 固定分配 UB；
- 两遍读取时按 UB 容量规划输入、统计量和输出的缓冲；双缓冲只有在容量和同步都满足时使用；
- 方差很小而均值很大时，避免用会发生灾难性抵消的单遍公式，按 reference 语义选择两遍或
  稳定算法。

## 重排、索引和广播：让输出直接落到最终布局

对 RoPE 交织、permute、gather、scatter、index_add 和广播类算子：

- 先识别索引是规则模式还是不规则模式；规则交织优先使用硬件 pattern 或连续搬运；
- 不规则 gather/scatter 才使用索引表，索引表应在矢量阶段生成，避免 Python/标量逐元素建表；
- 广播输入尽量按源行去重搬运，在 kernel 内按规则寻址，避免 host 侧物化完整 broadcast；
- 输出直接按最终布局计算，减少额外 transpose、contiguous 和中间复制；
- 输入、输出和临时 buffer 不要无意 alias；源、mask、累加器和输出的生命周期要分开；
- 非对齐尾部必须保留完整语义，使用正确的 DataCopyPad 或专用尾块路径；
- 索引 dtype、负索引、重复索引和写入顺序必须从 reference 与 case 中确认，不能根据算子名猜。

## Sort、TopK 和采样：先确定输出语义

先区分两种问题：

- 只需要阈值或掩码：可以考虑值域搜索和多遍矢量扫描；
- 需要有序值或有序索引：必须走排序或分段排序加归并，值域搜索不能替代排序。

还要确认：

- `k`、分组长度和 padding 后的实际范围；
- stable 排序和相等值（tie）的语义；
- reference 是保留恰好 `k` 个位置，还是保留所有满足 `value >= kth` 的元素；
- 计数、比较和选择使用向量路径，避免标量逐元素计数；
- `-inf`、NaN、概率归一化和 cumsum 的方向与 reference 一致。

## 量化、复制和索引写回：先冻结契约

量化类实现开始前，先从 reference 固定：

- 输入、scale、zero-point 和输出 dtype；
- rounding、clamp、特殊值及索引写回语义；
- 是否为 in-place，以及 clone 段和 update 段的依赖关系。

当 clone 流量远大于更新流量时，可以在保持语义的前提下把纯复制和更新分成不同的 kernel；
这只是实现方案，不能改变输出或评测入口。量化预处理不要搬到 CPU/host，避免额外 launch 和
改变数据契约；同一 stream 的顺序由设备队列保证，不要自行插入同步。

## Pooling 和窗口类算子：对齐限制属于实现方案

Pooling 的布局、窗口、反向累加和 data_format 必须以 reference 为准。不同的向量化布局会有
不同的 C/W/输出宽度对齐要求：

- 先明确 kernel 是整行搬运，还是按 C 维的 gather/scatter 搬运；
- 对齐后的行距和 padding 计入 UB 预算；
- 反向累加要处理写后读、重复索引和跨核累加顺序；
- 某一种路径不支持原题 shape 时，换路径或实现尾块；不能用守卫把合法 case 静默排除；
- 所有对齐守卫都必须对应真实硬件要求，并且保留清晰错误信息。

## 通用 host/tiling 检查

- 先按当前 SoC 确认核数、UB、对齐和 API 重载，不使用历史模板中的固定硬件常量；
- tile 需要同时满足并行度、UB 容量、搬运对齐、尾块和同步资源；
- host 传给 kernel 的 shape、stride、dtype、属性和输出大小必须来自 reference 的实际契约；
- 事件、队列和屏障必须配对；跨 pipe 依赖使用对应的事件，避免用全管屏障串行化热路径；
- 先保证全量原始 case 正确，再考虑对同类 shape 的通用性能改动。
